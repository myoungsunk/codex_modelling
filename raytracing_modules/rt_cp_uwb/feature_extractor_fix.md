# Feature Extractor Fix

## Scope

Week 2 Day 1 fixes lock the `gamma_cp` convention to:

- `gamma_cp = |cross-pol| / |co-pol|`
- In circular basis this is `reversed-hand / same-hand`
- For RHCP TX: `gamma_cp = |H(2,1)| / |H(1,1)|`
- For LHCP TX: `gamma_cp = |H(1,2)| / |H(2,2)|`

This makes the interpretation physically intuitive:

- LoS / direct path dominant: `gamma_cp` is low
- Odd-bounce NLoS dominant: `gamma_cp` is high

## Implementation Changes

- `+features/computeGammaCpVariants.m`
  - Now consumes the full circular-basis channel tensor.
  - Selects co-pol and cross-pol responses from `tx_handedness`.
  - Builds separate CIRs for same-hand and reversed-hand responses before computing `gamma_cp_*`.

- `+features/extractAllFeatures.m`
  - Resolves TX handedness from explicit input, TX primary port, or antenna metadata.
  - Passes the full circular channel tensor into `computeGammaCpVariants`.
  - Stores the handedness and circular-port indices used for `gamma_cp`.

- `+sanity/checkB1_cpHandednessReversal.m`
  - Plot label and details now use `gamma_cp` naming directly.

- `+sanity/checkB2_evenBounceHandedness.m`
  - Keeps the preservation metric for pass/fail, and also records `gamma_cp_db = reversed/same`.
